> 状态：设计稿（Phase 1–3 已实施，其余未实施）
> 日期：2026-10-20
> 关系：本文是 [`publishing-and-image-layout-design.md`](./publishing-and-image-layout-design.md) 的产品扩展。原文档中的「单一渲染器、图片排版引擎、发布包、微信 API、小红书半自动」仍然是基础；本文补齐 **图片生成、图片管理、运营闭环**，并把发布从「文档导出」升级为「作品 → 变体 → 发布」。
> 实施：Phase 1/2/3 已完成，见 [`phase-1-implementation.md`](./phase-1-implementation.md)、[`phase-2-implementation.md`](./phase-2-implementation.md)、[`phase-3-implementation.md`](./phase-3-implementation.md)。

## 0. 结论先行

### 0.1 产品判断

MarkCard Studio 现在是一条很顺滑的「Markdown → 卡片 → 导出」流水线。但发贴图场景的核心矛盾不是「卡片不够好看」，而是：

> **创作单位是「一篇作品」，不是「一个 Markdown 文件」；发布单位是「一个平台变体」，不是「一套 PNG」。**

所以这次扩展不应该只是加几个按钮，而要把产品重心从「排版工具」推进到「图文作品工作台」：

```text
灵感/选题 → 作品（主内容 + 图片序列 + 文案）
          → 平台变体（小红书 / 公众号 / 其他）
          → 发布前检查 → 发布 → 数据 → 复盘 → 复用
```

Jaaz 是这条链路上的**可选增强**：没有它，确定性封面/图集/发布仍然完整；有它，封面和配图的上限更高。不要把产品做成「没有 Jaaz 就不能用」。

### 0.2 四个能力环环相扣

| 能力 | 解决的问题 | 如果不做 |
| --- | --- | --- |
| 图片生成 | 没有封面、配图、背景，或者每次做图很慢 | 用户仍然要去别的工具找图，工作流断裂 |
| 图片管理 | 图片散落、重复、找不到、删了又怕引用断了 | 生成越多越乱，素材无法复用 |
| 一键发布 | 每个平台复制一遍、裁一遍、传一遍 | 内容做好了，发布仍然是最耗时的环节 |
| 运营 | 发完就忘，不知道哪篇有效、下一篇怎么改 | 只能「生产」，不能「迭代」 |

这四块必须按 **素材 → 生成 → 发布 → 运营** 的顺序打地基。先做发布按钮，后面素材和变体模型一改，全部返工。

### 0.3 十一条关键结论

1. **作品（Work）成为一等对象**：一个作品可以有多个平台变体，Markdown 只是其中一种来源。
2. **图片优先，但文字不交给模型**：AI 只生成画面/背景/插画，标题、正文、标签始终由应用排版，保证清晰、可编辑、可校对。
3. **确定性生成优先于 AI 生图**：渐变、几何、纹理、封面模板、图表、拼图、切图零成本、离线可用，应该先做。
4. **素材库是基础设施**：内容寻址（hash）、缩略图、引用关系、版权/来源信息，越早做越省事。
5. **发布是一套供应链**：平台变体、发布前检查、凭据、幂等、失败恢复，比「发布」按钮本身重要。
6. **微信可以真一键（草稿/发布）**，但有账号资质、IP 白名单、AppSecret 保管等硬前提。
7. **小红书个人号没有稳定可用的官方一键发布 API**（截至 2026-10）：首版必须老老实实做「一键准备 + 半自动」，浏览器自动化只能是可选实验能力。
8. **「发布就绪度」比「发布」更适合做核心交互**：让用户知道还差什么，而不是点下去才报错。
9. **运营要轻**：本地优先、手动可录入、围绕「节奏、复盘、复用」，不要做重型 BI。
10. **AI 内容要可追溯**：生成方式、模型、提示词、种子、版权状态随素材一起保存，满足平台标注和内部复盘需要。
11. **Jaaz 作为可选生图引擎接入，而不是重做一套画布**：MarkCard 负责排版/图集/发布，Jaaz 负责多模型生图与多轮精修；两者通过 API 或 handoff 协作，不复制 Jaaz 的代码与 UI。

### 0.4 建议落地顺序

```text
阶段 A 地基：作品模型 + 素材库 + 设置 v2 + 发布包
阶段 B 创作：封面工坊 + 确定性生成 + 图片编辑（只留 AI Provider 接口）
阶段 C 发布：平台变体 + 发布前检查 + 微信草稿/发布 + 小红书半自动
阶段 D 运营：内容管道 + 日历 + 数据录入/微信数据 + 复盘
阶段 E 进阶：A/B、AI 建议、浏览器桥、多账号
阶段 F 最后：Jaaz 接入（云端 API + handoff）
```

## 1. 用户与场景

### 1.1 目标用户

| 用户 | 典型内容 | 当前痛点 | 最想要的能力 |
| --- | --- | --- | --- |
| 知识/效率博主 | 长文拆图、清单、教程 | 一篇长文要手动拆成 9 张图，封面每次重做 | 长文转图集、封面模板、批量导出 |
| 独立开发者/产品人 | 产品更新、复盘、数据卡片 | 没有设计资源，配图靠截图 | 截图美化、数据图表、AI 配图 |
| 生活方式博主 | 探店、旅行、手帐、好物 | 图很多，选图/裁图/排序很花时间 | 图集编排、批量裁切、封面 A/B |
| 品牌/新媒体运营 | 系列内容、活动、矩阵 | 多平台改文案、改尺寸、发布琐碎 | 平台变体、发布检查、日历、数据复盘 |
| 设计师/摄影爱好者 | 作品集、照片组 | 排版工具和素材管理割裂 | 模板、拼图、素材库、版权信息 |

首版建议聚焦 **个人创作者 + 小团队运营**，不碰大型品牌矩阵和多人协作。

### 1.2 核心任务（Jobs To Be Done）

- 当我有一篇长文时，我想在 10 分钟内得到一套可直接发小红书的图，而不是逐页截图。
- 当我只有一堆照片时，我想快速选图、排序、套模板、写短文案，做出一篇像样的图文笔记。
- 当我要同步发公众号和小红书时，我不想重新裁图、改标题、数字数。
- 当我生成/收集了很多图片后，我想快速找到、复用、替换，而不是在文件夹里翻。
- 当我发完内容后，我想知道哪篇有效、为什么有效、下一篇怎么改。
- 当我想做系列内容时，我想复用上一次的模板、封面风格和 CTA，而不是从零开始。

### 1.3 三条端到端旅程

**旅程 A：长文 → 双平台图文**

```text
打开 Markdown
→ 切换「图集」视图，自动分页成 7 张
→ 封面工坊：选模板 + 生成背景 + 排版标题
→ 调整图片顺序/焦点/说明
→ 生成「小红书变体」和「公众号图片消息变体」
→ 发布检查：标题 18/20、图片 7/18、封面安全区通过
→ 小红书：复制文案 + 打开创作平台 + 显示图片文件夹
→ 公众号：上传素材 → 建草稿 → 在后台确认后发布
→ 24 小时后记录/拉取数据 → 复盘卡
```

**旅程 B：照片 → 图集**

```text
拖入 12 张照片
→ 自动去重、生成缩略图、按色彩/清晰度排序（可手动改）
→ 选 9 张，套「杂志拼贴」模板
→ 批量裁成 3:4，自动避开人脸/主体（焦点可调）
→ 写标题、正文、标签
→ 一键准备发布包
```

**旅程 C：系列内容**

```text
打开上一期作品 →「另存为模板」
→ 保留主题、封面版式、页脚、CTA、标签结构
→ 替换正文/图片
→ 批量生成 4 期封面
→ 放入内容日历，按周提醒
→ 月度复盘：哪一期封面/标题效果最好
```

### 1.4 成功指标

| 层级 | 指标 | 目标（首版） |
| --- | --- | --- |
| 北极星 | 每周成功发布的图文作品数 | 相对基线 +50% |
| 效率 | 从「内容就绪」到「发布完成」的时间 | 小红书 ≤ 3 分钟，公众号 ≤ 2 分钟 |
| 复用 | 使用素材库/模板的作品占比 | ≥ 60% |
| 质量 | 发布失败率 | < 5%（不含平台侧审核失败） |
| 质量 | 因素材缺失/尺寸不符导致的返工 | < 2% |
| 留存 | 发布后 7 天内创建下一篇的用户占比 | ≥ 40% |
| 安全 | 凭据泄漏事件 | 0 |

## 2. 产品模型

### 2.1 五个核心对象

| 对象 | 定义 | 关键字段 | 生命周期 |
| --- | --- | --- | --- |
| **作品 Work** | 一次内容创作的容器 | 标题、类型、主内容、图片序列、主文案、主题、画布 | 草稿 → 就绪 → 已发布 → 归档 |
| **素材 Asset** | 可复用的图片/贴纸/背景/生成结果 | hash、路径、尺寸、来源、版权、AI 信息、标签 | 导入 → 使用 → 归档/删除 |
| **变体 Variant** | 面向某个渠道的发布版本 | 渠道、标题/正文/标签覆盖、图片顺序、封面、检查结果 | 草稿 → 就绪 → 发布中 → 已发布/失败 |
| **发布记录 PublishRecord** | 一次真实发布尝试 | 渠道、模式、远端 ID、状态、错误、时间 | 进行中 → 成功/失败 → 可重试 |
| **指标快照 MetricSnapshot** | 某个时间点的数据 | 阅读、点赞、收藏、评论、分享、涨粉、点击 | 追加式，不覆盖 |

辅助对象：**灵感 Idea**、**日历排期 CalendarSlot**、**实验 Experiment**、**品牌套件 BrandKit**、**系列 Series**。

### 2.2 与现有 Markdown 文档的关系

- 现有 `useStudioDocument.js` 继续负责「文档编辑、解析、分页、预览、导出」这一条链路，不把素材库/发布/运营状态塞进去。
- 新增 `useWork.js` 负责「作品级元数据」：作品类型、封面、图片序列、主文案、平台变体、发布状态。
- 一个作品可以：
  - 由 Markdown 文档生成（`source.kind = "markdown"`）；
  - 由图片集创建（`source.kind = "assets"`）；
  - 由模板/上一期作品复制（`source.kind = "template"`）。
- Markdown 文档仍是「文本源」；作品保存时记录 `source.path` 与 `contentHash`，但不复制整篇正文到作品文件（可选保存快照，便于分享）。

### 2.3 三种创作模式

| 模式 | 主输入 | 适合 | 首版 |
| --- | --- | --- | --- |
| **文档模式** | Markdown | 长文、教程、清单、知识卡片 | 已有，继续增强 |
| **图集模式** | 图片 + 短文案 | 小红书图文、公众号图片消息、朋友圈 | 新增 |
| **海报模式** | 单张主图 + 标题 | 封面、活动海报、金句卡、二维码海报 | 新增 |
| （延伸）长图模式 | 多页拼接 | 公众号长图、微博长图 | 复用现有长图导出 |

三种模式共享：主题、画布、素材库、封面工坊、发布变体、发布检查。

### 2.4 信息架构与导航

当前是三栏工作台（编辑 / 预览 / 设置）。直接加第四个侧栏会挤，建议改成 **顶部一级工作区 + 右侧检查器**，采用「3 + 1」：

```text
┌──────────────────────────────────────────────────────────────┐
│ Logo   创作   发布   运营               [⌘K] [素材库] [设置]   │
├──────────┬───────────────────────────────────┬───────────────┤
│ 文档/页面 │                                   │ 检查器         │
│ 或素材    │           画布 / 预览               │ 设计/生成/发布 │
│ 或列表    │                                   │ 检查/变体      │
├──────────┴───────────────────────────────────┴───────────────┤
│ 状态栏：字数 / 页数 / 素材数 / 发布就绪度 / 保存状态           │
└──────────────────────────────────────────────────────────────┘
```

- **创作**：一级工作区；内部再分「写作 / 图集 / 海报」，共享主题、画布、素材、导出。
- **发布**：作品列表 / 变体 / 发布队列 / 历史。
- **运营**：概览 / 日历 / 数据 / 复盘。
- **素材库**：全局浮层，任何模式都能打开；支持拖拽插入。
- **发布作品**：主按钮，打开三步发布弹窗；旁边显示就绪度。

不建议首版引入 Vue Router。用 `App.vue` 里的 `activeWorkspace` 状态切换视图即可；素材库用全屏 Dialog/Overlay，保留「不离开当前作品」的体验。更细的线框、组件树、响应式与状态归属见 [`ui-architecture-design.md`](./ui-architecture-design.md)。

### 2.6 状态机

**作品**

```text
draft ──内容完整──▶ ready ──发布成功──▶ published ──归档──▶ archived
  ▲                  │
  └────继续编辑───────┘
```

**变体**

```text
draft ──检查通过──▶ ready ──进入队列──▶ preparing ──▶ uploading
  ▲                   │                              │
  └──修改覆盖─────────┘                              ▼
                                              awaiting_confirm
                                                      │
                                      ┌───────────────┴───────────────┐
                                      ▼                               ▼
                                  published                        failed
                                                                      │
                                                                      └──retry──▶ preparing
```

**发布记录**：`queued → running → succeeded | failed | canceled`。任何一步失败都保留已完成的上传结果，重试时只补缺失部分。

## 3. 图片生成

### 3.1 五个设计原则

1. **确定性优先**：模板、渐变、几何、纹理、图表、拼图、切图不依赖网络和模型，先保证「随时能做出可用的图」。
2. **生成与排版分离**：AI 只负责画面；标题、正文、标签、页码、水印由应用用 HTML/SVG 排版。这样文字永远清晰、可编辑、可校对，也避免模型生成乱码。
3. **可替换**：任何生成结果都先进素材库，再被作品引用；替换素材不改变版式，方便反复迭代。
4. **可追溯**：保存 provider、model、prompt、negative prompt、seed、参考图、生成时间、成本；导出/发布时可按需带 AI 标识。
5. **可降级**：没有 API Key、断网、额度用完时，自动回退到确定性生成；不阻塞主流程。

### 3.2 能力矩阵

| 能力 | 类型 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- |
| 封面模板 | 确定性 | 标题/副标题/主题/画布 | 封面 | P0 |
| 渐变/网格/噪点/纸张纹理 | 确定性 | 主题色/种子/比例 | 背景 | P0 |
| 几何/拼贴/贴纸组合 | 确定性 | 主题/版式/素材 | 装饰图 | P0 |
| 图表/信息图 | 确定性 | Markdown 表格/列表 | SVG/PNG | P1 |
| 拼图/九宫格/胶片条 | 确定性 | 多张素材 | 合成图 | P0 |
| 长图切片/九宫格切图 | 确定性 | 长图/单图 | 多张图 | P1 |
| 截图美化 | 确定性 | 截图/代码/网页 | 带框卡片 | P1 |
| 图片编辑（裁切/焦点/滤镜/模糊/马赛克/文字） | 确定性 | 图片 | 新素材 | P0 |
| 背景移除/超分 | 本地或 AI | 图片 | 透明 PNG/放大图 | P2 |
| 文生图（封面背景/配图/贴纸/纹理） | AI | 提示词/风格/比例 | 2–4 张候选 | P1 |
| 图生图（风格迁移/重绘） | AI | 参考图 + 提示词 | 变体 | P2 |
| 局部重绘/扩图 | AI | 蒙版/图片 | 修改图 | P2 |
| 图片描述/Alt 文本 | AI/本地 | 图片 | 文本 | P1 |
| 标题/文案建议 | LLM | 正文/平台 | 候选文案 | P2 |

> Jaaz 不是单独一种能力，而是上述 AI 生图能力的聚合入口：一个 Token 可选多个模型、支持参考图/任务轮询。详见 3.7.1。

### 3.3 封面工坊（Cover Studio）

封面是图文内容的第一生产力，建议做成独立的全屏/大弹窗编辑器，而不是设置面板里的几个下拉框。

**核心能力**

- **模板**：首批 12–16 个，按风格分组（编辑网格、杂志、手帐、极简、科技、复古、拼贴、渐变、摄影、纯文字）。
- **结构**：背景层（纯色/渐变/纹理/图片/AI 生成）+ 主标题 + 副标题 + 标签/栏目 + 贴纸/装饰 + 品牌 Logo + 页码。
- **文字排版**：字号自适应、最多 3 行、自动断行、避免孤字、标题安全区、对比度检查、描边/阴影/色块。
- **平台规格**：小红书 3:4、公众号封面 2.35:1 + 1:1、朋友圈 1:1/4:5、方形 1:1、抖音 9:16；同一封面自动生成多平台裁切版本。
- **安全区**：显示平台 UI 遮挡区域（尤其公众号封面在小图流里的裁切），标题/Logo 不进入危险区。
- **批量**：系列内容一次生成 N 期封面，只替换期数/标题，保持风格一致。
- **A/B**：同一作品保存 2–3 个封面候选，发布时选用，运营阶段对比效果。

**与现有代码的关系**

- 复用 `THEME_LIST` 的主题色、`base-card.css` 的字体与圆角变量；
- 封面画布复用 `CardArtwork` 的卡片标记与 `useCardExport` 的渲染管线；封面模板用独立 DOM/SVG，不新增第二套卡片内容；
- 新增 `src/config/coverTemplates.js`、`src/composables/useCoverStudio.js`、`src/components/create/CoverStudio.vue`；
- 导出走统一的 Renderer，保证预览与导出尺寸一致。

**封面模板数据结构**

```js
{
  id: "cover-editorial-01",
  name: "编辑网格",
  category: "editorial",
  ratios: ["3:4", "1:1", "2.35:1"],
  slots: ["background", "kicker", "title", "subtitle", "meta", "logo"],
  defaults: {
    font: "sans",
    titleSize: 0.12,      // 相对画布宽度
    align: "left",
    padding: 0.08,
    safeArea: 0.06,
  },
  render: "cover-editorial-01", // 对应 CSS/DOM 模板
}
```

### 3.4 配图、背景与图表

- **背景生成器**：渐变（线性/径向/网格渐变）、噪点、纸张、网格、半调、Riso 错位、蓝图、Y2K 铬面、阴影/光斑。支持 seed，保证系列一致。
- **配图生成器**：用几何形状、贴纸、图标、色块拼出「不空洞」的配图，适合没有摄影素材的知识类内容。
- **图表**：从 Markdown 表格生成柱状图/折线图/环形图/进度条/时间线；从列表生成步骤图/清单图；从引用生成金句卡。
- **截图美化**：浏览器框、手机框、代码窗口、阴影、圆角、背景色、标注箭头/高亮；适合产品更新、代码教程。
- **二维码/引导图**：二维码 + 头像 + 一句话 CTA + 品牌色；支持公众号/小红书/私域引流。
- **图片说明（caption）**：在图下方或浮层显示，固定行高，避免分页高度不可预测（与图片排版引擎一致）。

### 3.5 图集编排与切图

**图集编排器**是「图片为主」场景的核心界面：

```text
┌ 图集 ─────────────────────────────────────────────┐
│ 封面   [图1] [图2] [图3] [图4] [图5] ...  [+ 添加] │
│                                                    │
│ 左：素材抽屉/最近使用     中：当前页大图            │
│ 右：版式/比例/焦点/说明/替换                        │
│ 底部：顺序拖拽、批量裁切、套模板、生成变体           │
└────────────────────────────────────────────────────┘
```

能力：

- 拖拽排序、批量选择、按时间/颜色/清晰度排序；
- 统一比例（3:4 / 1:1 / 4:5 / 9:16），支持「智能填充」和「留白」；
- 焦点裁切（object-position），人脸/主体可手动调整；
- 一页多图（2/3/4/6/9 宫格）、跨页套图、封面单独版式；
- 批量加说明、批量加页码、批量套贴纸；
- 九宫格切图：把一张长图/海报切成 9 张，带安全边距和顺序编号；
- 长图切片：按内容块/固定高度切片，避免切断文字和图片；支持重叠 10–20px 方便拼接；
- 导出前检查：尺寸、体积、透明背景、重复图、空页。

### 3.6 图片编辑（轻量，不做完整 PS）

首版只做「发布前必须用」的编辑：

| 功能 | 说明 | 优先级 |
| --- | --- | --- |
| 裁切/旋转/翻转 | 固定比例 + 自由裁切 + 焦点 | P0 |

| 文字/箭头/框选/高亮 | 截图标注 | P1 |
| 圆角/边框/阴影/背景填充 | 截图美化 | P1 |
| 去背景 | 本地模型或 AI，输出透明 PNG | P2 |
| 超分 | 2x/4x，发布前放大 | P2 |

#### 3.7.1 Jaaz 接入（后期实现）

> 命名说明：以下按 **Jaaz**（[jaaz.app](https://jaaz.app)，开源 AI 设计 Agent，仓库 [`11cafe/jaaz`](https://github.com/11cafe/jaaz)）理解，用户口述的「Jazz AI」按同一产品处理。如果你指的是另一个同名服务，只需替换本节的 endpoint / auth / 模型字段，产品层与 `ImageProvider` 契约不变。
>
> 本地已确认：同级 Jaaz 源码 v1.0.30，默认端口 `57988`；当前按个人使用设计，不涉及商业分发。

**为什么接 Jaaz，而不是自己重做一套生图**

- Jaaz 已经聚合了 GPT-Image、Flux Kontext、Imagen、Midjourney、Seedream、Recraft 等模型，覆盖文生图、图生图、风格参考、局部重绘、角色一致性、多轮迭代。
- Jaaz 的强项是「无限画布 + Agent + 多轮精修」；MarkCard 的强项是「卡片排版 + 图集编排 + 双平台发布」。两者是互补关系，不应该把 Jaaz 的整个画布搬进 MarkCard。
- 因此 MarkCard 只接 **生图能力**：生成结果直接进素材库，再被封面/图集/发布引用；需要深度精修时 handoff 到 Jaaz，而不是复制它的 UI。

**从 Jaaz 借用的能力（映射到 MarkCard）**

| Jaaz 能力 | 在 MarkCard 的落点 | 首版 |
| --- | --- | --- |
| 多模型聚合 | 模型下拉、默认模型、按用途推荐 | 是 |
| 文生图 | 封面背景、内页配图、贴纸、纹理 | 是 |
| 图生图 / 参考图 | 风格锁定、产品图/角色一致性 | 是 |
| 异步任务轮询 | 长任务进度、失败恢复、任务 ID | 是 |
| 多轮迭代 | 生成历史「基于这张继续改」 | 是 |
| 局部重绘 / 扩图 | 图片编辑里的「局部重绘」 | P2 |
| 无限画布 / Agent | handoff 到 Jaaz 精修 | 是（轻量） |
| 视频生成 | 不做（非目标） | 否 |

```text
┌──────────── MarkCard ────────────┐
│ 封面 / 图集 / 发布 / 素材库       │
│ prompt builder / 校验 / 入库      │
└──────────────┬───────────────────┘
               │ prompt + 参考图 + 比例
               ▼
┌──────────── Jaaz ────────────────┐
│ 多模型路由 / 任务 / Agent / 画布  │
└──────────────┬───────────────────┘
               │ image URL / file
               ▼
       素材库（hash 入库）→ 作品 → 发布
```

**三种接入模式**

| 模式 | 做法 | 适合 | 首版 |
| --- | --- | --- | --- |
| **A. 云端 API（推荐）** | 用户在 MarkCard 填 Jaaz API Token；Rust 调 `https://jaaz.app/api/v1`；结果下载入库 | 有 Jaaz 订阅、想一键生成 | 是 |
| **B. 本地 handoff** | MarkCard 导出「生成 brief + 参考图 + 比例」，打开 Jaaz 桌面端；用户精修后把结果拖回素材库 | 隐私敏感、想用本地 ComfyUI、需要画布精修 | 是（轻量） |
| **C. 本地 sidecar** | 检测/启动 Jaaz 本地 server，调用其 `/api/magic` 或工具接口 | 完全本地、可接受额外进程 | 可选 |

| 维度 | Jaaz 云端 API | Jaaz handoff | 直接接单一 provider |
| --- | --- | --- | --- |
| 模型覆盖 | 高（聚合） | 取决于用户 Jaaz 配置 | 低（单一） |
| 上手成本 | 需 Jaaz Token | 需安装 Jaaz | 需各 provider Key |
| 隐私 | prompt/参考图出境 | 本地 | 取决于 provider |
| 自动化 | 高 | 低（手动精修） | 高 |
| 成本 | Jaaz 订阅/额度 | Jaaz/本地算力 | provider 计费 |
| 维护 | 接口变更风险 | 版本兼容 | 多适配器维护 |

首版建议 **A + B**：A 解决「快」，B 解决「精修/隐私」。C 依赖 Jaaz 的本地进程和内部接口，维护成本高，放到阶段 E。

**云端 API 契约**

以下来自 Jaaz 当前开源客户端 `server/tools/image_providers/jaaz_provider.py` 与 `server/services/jaaz_service.py` 的实际调用方式。它属于 **非公开/半公开接口**，可能随 Jaaz 版本变化，必须封装在适配器里，不能散落到 UI。若用于商业产品，建议先联系 Jaaz 确认 API 使用授权、配额与稳定性承诺，不要把内部接口当作长期合同。

```text
Base URL : https://jaaz.app/api/v1/
Auth     : Authorization: Bearer <JAAZ_API_TOKEN>
```

1）同步生成（OpenAI / Replicate 兼容）：

```http
POST /image/generations
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "prompt": "editorial still life, warm paper, soft shadow, no text",
  "model": "flux-kontext-pro",
  "aspect_ratio": "3:4",
  "input_image": "data:image/jpeg;base64,..."
}
```

> `model` 以 `openai/` 开头时走 OpenAI 风格字段（`n`、`size`、`input_images`）；否则按 Replicate 风格处理（单张 `input_image`）。模型 ID 以 Jaaz 账号实际可用为准。

响应为 OpenAI 风格：

```json
{
  "created": 1760000000,
  "data": [{ "url": "https://.../result.jpg" }]
}
```

2）Midjourney / 异步任务：

```text
POST /image/midjourney/generation   → { "task_id": "..." }
GET  /task/{task_id}                → { "success": true, "data": { "found": true, "task": { "status": "succeeded", "result_url": "..." } } }
```

3）任务检索兜底：

```text
POST /task/search   body: { "prompt": "...", "type": "image" }
```

4）Magic（可选，用于局部重绘/在 Jaaz 中继续）：

```text
POST /image/magic   body: { "image": "data:image/..." } → { "task_id": "..." }
```

**实现要点**

- `model` 以 Jaaz 账号实际可用为准，不硬编码「永久模型列表」。默认给候选（可能带 `openai/` 前缀）：`openai/gpt-image-1`、`flux-kontext-pro`、`flux-kontext-max`、`imagen-4`、`midjourney`、`seedream-3`、`recraft-v3`；设置里允许手填模型 ID。
- `aspect_ratio` 支持 3:4 / 1:1 / 16:9 / 9:16 / 4:5；2.35:1 这类公众号封面比例若模型不支持，先按 16:9 生成，再本地裁切/留白。
- 单张参考图用 `input_image`；多张参考图用 `input_images`（OpenAI 风格）；参考图先压缩到长边 ≤ 1536，避免请求过大。
- 一次生成 1–4 张候选；默认 1 张，封面场景可 4 张。批量时串行或并发 2，避免限流。
- 支持 seed 的模型才写 seed；不支持的模型用 prompt + 参考图 + 模型默认随机性，不承诺可复现。
- 结果下载后走 `import_generated_asset`，保存 provider/model/taskId/prompt/比例/耗时；图片文件不经过 base64 IPC 回传。
- 超时/失败时先查 `/task/search` 兜底，再决定是否重试；避免重复扣费与重复入库。
- 取消：停止轮询/下载；已提交的云端任务可能仍会计费，UI 要说明。

**UI**

- 设置 → 生成 → Jaaz：
  - API Token（只写 Keychain，显示「已配置」；Token 获取入口以 Jaaz 账户页为准）
  - Base URL（默认锁定官方；自建/代理需显式开启并校验）
  - 默认模型、默认比例、候选数量
  - 「测试连接」：调用一次低成本请求或 `/task/search`，返回账号/模型可用性
  - 额度/账单入口：打开 Jaaz 账户页，不在应用内保存账单信息
- 生成面板：
  - 模型、比例、参考图、提示词（由 `promptBuilder` 预填）
  - 「生成 4 张」→ 结果网格 → 「设为封面 / 插入当前页 / 入库 / 在 Jaaz 中精修」
  - 结果卡显示：模型、尺寸、耗时、任务 ID、AI 标识
- 「在 Jaaz 中精修」：
  - 导出 `jaaz-brief.json`：prompt、negative、比例、参考图路径、目标用途
  - 打开 Jaaz（深链或系统打开）
  - 用户完成后把文件拖回素材库，或从 Jaaz 的 `user_data/files` 导入

**错误映射**

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 401 / 403 | Token 无效、过期、无权限 | 重新配置；日志不回显 Token |
| 402 / 429 | 额度不足 / 限流 | 显示额度或重试时间；禁止连续重试 |
| 400 | prompt / model / 比例不支持 | 字段级提示；建议换模型或比例 |
| 404 | endpoint 变更 | 提示「Jaaz 接口可能已升级」，保留 handoff |
| 5xx | Jaaz 服务异常 | 指数退避 2 次；降级 handoff/确定性生成 |
| task failed | 生成失败/内容审核拒绝 | 显示原因；保留 taskId 便于排查 |
| timeout | 任务超时 | 允许继续轮询；超过 5 分钟提示稍后查看 |

**安全、隐私与许可（重要）**

- Token 只存 OS Keychain；请求由 Rust 发出；日志、错误、导出包、崩溃报告中都不出现 Token。
- 云端模式会把 prompt 和参考图发给 Jaaz；首次开启必须明确同意，并提示「敏感内容请用本地 handoff / ComfyUI」。
- **Jaaz 采用双许可（Community + Commercial）**。其社区许可限制修改、翻译、逆向、衍生、再分发，以及在商业产品中嵌入；商业分发/修改/团队部署需要商业许可。当前按**个人使用**设计，风险相对低；但仍**不复制、不内嵌、不修改、不再分发** Jaaz 源码。云端模式只通过 HTTP 调用 Jaaz，handoff 模式只启动用户已安装的 Jaaz；若未来要商业分发或打包 Jaaz 二进制，必须重新评估商业许可。
- MarkCard 自身是 GPL-3.0；把 Jaaz 作为独立服务调用是否构成衍生作品，需结合具体分发方式判断；个人使用不涉及分发，风险较低。
- 不提供「去除 AI 标识」；Jaaz 生成的图片同样记录 provider/model/taskId，并按平台要求标识。
- 遵守 Jaaz 的使用条款与内容政策；不绕过额度、审核、验证码。

#### 3.7.2 凭据与请求边界

凭据只存 OS Keychain（Rust），前端只看到「已配置/未配置」；请求可由 Rust 发出，避免前端 CORS 和密钥暴露。若走前端直连，也必须从 Rust 取短期凭据，且不落 localStorage。

#### 3.7.3 提示词构建器

不要让用户从空白框开始。提示词由「结构化表单 + 可编辑文本」组成：

```text
主题：<作品标题/当前页摘要>
用途：封面背景 / 内页配图 / 贴纸 / 纹理
风格：编辑摄影 / 扁平插画 / 手绘 / 3D / 复古印刷 / 极简几何
构图：留白左侧 / 中心主体 / 俯拍 / 平铺
色彩：跟随主题 / 品牌色 / 暖色 / 冷色 / 黑白
光线：柔和 / 硬光 / 窗光 / 霓虹
比例：3:4 / 1:1 / 16:9 / 9:16
负面：文字、水印、logo、人脸、手、杂乱
参考图：可选（图生图/风格锁定）
```

系统提示固定包含「不要生成文字、不要水印、不要 UI」。生成后由应用排版标题。

#### 3.7.4 一致性与系列化

- **风格锁定**：保存一组 `stylePreset`（提示词后缀 + 参考图 + seed + 模型），系列内容复用。
- **角色/产品一致**：参考图 + 相同 seed + 相同风格提示；不承诺 100% 一致，UI 说明「尽量一致」。
- **封面系列**：同一模板 + 同一背景生成器，只换标题/期数，保证视觉连续。
- **批量**：一次生成 4 张候选，选 1 张入库；其余可保留在「生成历史」。
- **缓存**：`hash(prompt + model + seed + size + refs)` 命中缓存直接复用，省钱提速。

#### 3.7.5 成本与体验

- 生成前显示预估费用/额度；支持「低清预览 → 选定后高清」。
- 进度用 `generation://progress` 事件；支持取消；并发限制 2。
- 失败重试 1–2 次，超时/限流给出可操作提示。
- 生成历史保留最近 100 条（不含大图，图在素材库），可重新跑同一提示词。
- 断网/无 Key 时，面板顶部提示「当前仅确定性生成可用」。

#### 3.7.6 合规与标识

- 保存 `ai.generated`、provider、model、prompt hash、生成时间；发布前可按平台要求添加「AI 生成」标识。
- 不提供「去除 AI 标识」的能力；导出 manifest 保留来源。
- 内置基本安全提示：不生成真人肖像/违法/暴力/侵权内容；依赖供应商的内容审核。
- 用户需确认对参考图拥有使用权；素材库记录版权状态，未知版权在发布前给 warning。
- 关注《人工智能生成合成内容标识办法》等国内要求，显式标识 + 元数据标识都预留字段；具体合规文案需上线前复核。

## 4. 图片管理

### 4.1 定位

素材库不是「文件浏览器」，而是 **可复用、可追溯、可清理的内容资产层**。它要回答四个问题：

1. 这张图从哪来？（导入/生成/导出/截图/贴纸）
2. 它被谁用了？（作品、页面、变体）
3. 我还能不能用？（版权、AI 标识、是否重复）
4. 删了会不会坏？（引用完整性）

### 4.2 素材模型

| 字段 | 说明 |
| --- | --- |
| `id` | 内容 hash（sha256），天然去重 |
| `kind` | image / sticker / background / icon / generated / export |
| `path` | 内容寻址路径，如 `assets/9f/2c/<hash>.jpg` |
| `thumb` | 320px WebP 缩略图 |
| `width/height/format/bytes` | 基础信息 |
| `source` | import / generated / export / sticker / wallpaper / screenshot |
| `ai` | 是否生成、provider、model、promptHash、label |
| `rights` | license、author、sourceUrl、attribution |
| `tags` | 用户标签 + 自动标签（颜色/比例/来源） |
| `focal` | 默认焦点 |
| `dominantColors` | 主色，用于配色建议 |
| `alt` | 无障碍描述，可 AI/手动生成 |
| `usage` | 引用列表（workId + ref） |
| `createdAt/updatedAt` | 时间 |
| `deletedAt` | 软删除，30 天可恢复 |

### 4.3 核心功能

| 能力 | 说明 | 优先级 |
| --- | --- | --- |
| 导入 | 拖拽、粘贴、文件选择、文件夹导入、截图 | P0 |
| 去重 | 内容 hash 相同直接复用，提示「已存在」 | P0 |
| 缩略图 | 后台生成 WebP，网格懒加载 | P0 |
| 组织 | 标签、收藏、合集、智能合集 | P1 |
| 搜索 | 文件名、标签、Alt、提示词、颜色 | P1 |
| 筛选 | 类型、比例、来源、AI/非 AI、未使用、缺失 | P1 |
| 使用 | 拖入画布/编辑器、设为封面/背景、插入 Markdown | P0 |
| 替换 | 保持引用与版式，替换图片；保留旧版本 | P0 |
| 批量 | 标签、移动、导出、压缩、转格式、重命名 | P1 |
| 清理 | 未使用、重复、超大、缺失文件；回收站 | P1 |
| 打包 | 作品/项目导出为 `.mcard`，素材相对路径 | P1 |
| 版权 | license、署名、来源链接；发布前提示 | P1 |
| 隐私 | 默认剥离 EXIF GPS；马赛克/遮挡 | P0 |

### 4.4 引用完整性与删除策略

- 素材被引用时，`usage` 记录 `workId + ref`；删除前检查：
  - 无引用：可直接进回收站；
  - 有引用：提示「被 N 个作品使用」，默认阻止，提供「查看引用 / 强制归档」。
- 作品打开时校验素材存在；缺失时显示占位图，并提供「重新链接 / 从素材库选择 / 忽略」。
- 替换素材使用「引用替换」而不是「改文件内容」，避免缓存和导出不一致。
- 回收站 30 天；恢复时保留原 `id` 和引用。
- 删除作品不自动删除素材（素材可能被其他作品复用）；提供「清理未使用素材」。

### 4.5 存储与性能

**存储布局（应用数据目录）**

```text
<appData>/markcard/
├── library/
│   ├── index.json          # 素材元数据（MVP）
│   ├── assets/9f/2c/...    # 原图，内容寻址
│   └── thumbs/9f/2c/...    # WebP 缩略图
├── works/
│   └── work_.../work.json
├── publish/
│   ├── records.json
│   └── bundles/...
├── metrics/
│   └── snapshots.json
└── cache/
    └── generation/...
```

- **MVP 用 JSON 索引 + 原子写**（临时文件 + rename），规模 < 5,000 素材足够；超过后迁移 SQLite（只换存储层，不改 UI）。
- 索引写入串行化，避免并发覆盖；启动时校验 schemaVersion，坏数据回退备份。
- 缩略图 320px WebP；原图不重复压缩；导出/发布时再按渠道压缩。
- 素材网格虚拟滚动；搜索在内存索引上做；颜色筛选用主色数组。
- 项目内素材：文档同目录 `assets/` 保持相对路径可移植；导入时复制到库并建立映射，不移动用户原文件（除非用户选择「整理到项目」）。

**全局库 vs 项目目录（已确认：全局库为主 + 项目镜像）**

| 维度 | 全局素材库 | 项目目录 `assets/` |
| --- | --- | --- |
| 位置 | 应用数据目录 `library/` | 文档同目录 `assets/` |
| 作用 | 内容主库、索引、去重、标签、版权、使用关系 | Markdown 引用镜像，保证文档可移植 |
| 范围 | 所有作品/项目 | 当前项目/文档 |
| 复用 | 高，hash 去重，跨作品复用 | 低，只服务当前项目 |
| 可移植 | 通过 `.mcard` 导出 | 复制文件夹即可打开 |
| 引用方式 | `assetId` + 索引 | 相对路径 `assets/<hash>.<ext>` |
| 删除 | 无引用才可清理 | 先移除 Markdown 引用，再清理 |

- **全局库是内容主库**：原图只按 hash 存一份，负责搜索、标签、版权、AI 信息、使用关系。
- **项目目录是引用镜像**：只放当前项目实际引用的素材，Markdown 用相对路径，保证换机器/换编辑器仍能打开。
- **导入流程**：hash → 库中不存在则复制进库 → 确保项目 `assets/<hash>.<ext>` 存在（复制/硬链接，失败回退复制）→ 插入相对路径 → 记录 `assetId ↔ projectPath` 映射。
- **导出 `.mcard`**：只收集被引用的素材，写入 `assets/` + `manifest.json`；不打包整个全局库。
- **删除规则**：先移除项目引用；全局库素材只有在没有任何项目引用时才允许清理；项目镜像不单独参与全局搜索。
- **不使用绝对路径/符号链接**：绝对路径换机器会断；符号链接在 Windows/移动硬盘上不可靠。


### 4.6 版权、隐私与 AI 标识

- `rights.license` 枚举：`own` / `cc0` / `cc-by` / `cc-by-sa` / `permission` / `unknown`。
- `unknown` 不阻止编辑，但发布前给 warning：「版权状态未知，请确认使用权」。
- OpenMoji 等第三方素材保留原有署名与许可证；导出/发布包保留 `attribution`。
- 默认剥离 EXIF（GPS、设备、拍摄时间），可在素材详情里选择保留版权字段。
- 截图/聊天记录提供一键马赛克；发布前检查是否含手机号/二维码/地址（可做简单正则提示，不承诺识别所有隐私）。
- AI 素材显示「AI 生成」徽标；`ai.label` 可按平台要求写入发布文案或 manifest。

| --- | --- | --- | --- |
| 微信公众号·图片消息 | 上传图片 → 建草稿 →（可选）发布，全链路 API | 账号必须有接口权限、IP 白名单；平台审核不可控 | 真一键（默认存草稿） |
| 微信公众号·图文消息 | 上传正文图 + 封面 → 建草稿 | HTML/CSS 限制多，复杂排版需降级 | 一键草稿，排版简化 |
| 小红书·图文 | 生成发布包、复制文案、打开创作平台、显示图片文件夹 | 个人号无稳定可用的官方发布 API；自动化有风控/条款风险 | 一键准备 + 半自动 |
| 小红书（有资质） | 开放平台 OAuth/笔记接口 | 需商家/服务商资质，接入周期长 | 后续适配器 |
| 本地发布包 | 全部素材 + manifest 落盘 | 无 | 始终可用，兜底 |

> 产品文案要诚实：公众号叫「一键发布/存草稿」，小红书叫「一键准备发布」。不要在 UI 上暗示小红书会自动发出去。

### 5.2 发布模型与流程

```text
作品 Work
  → 选择渠道（可多选）
  → 为每个渠道生成变体 Variant（文案/图片/封面/裁切覆盖）
  → 发布前检查 Preflight（blocker / warning / info）
  → 生成发布包 Bundle（manifest + images + copy）
  → 渠道适配器
      ├─ 微信 API：素材上传 → 草稿 →（可选）发布 → 状态轮询
      ├─ 小红书：复制文案 + 打开创作平台 + 打开图片文件夹 + 清单
      └─ 本地：仅落盘
  → 发布记录 PublishRecord
  → 运营：指标快照 + 复盘
```

**关键原则**

- 渠道适配器只消费 **发布包**，不再读 Markdown；
- 一个作品可以同时有多个变体，变体之间共享素材但覆盖文案/顺序/封面；
- 发布前检查是阻断式的：blocker 未解决不能点发布；
- 所有发布动作可取消、可重试、可追溯。

### 5.3 发布前检查与「就绪度」

**就绪度** = 100 - blocker 扣分 - warning 扣分，用于顶部进度环和作品列表排序。

检查项：

| 代码 | 级别 | 说明 |
| --- | --- | --- |
| `EMPTY_CONTENT` | blocker | 标题/图片为空 |
| `IMAGE_COUNT_OUT_OF_RANGE` | blocker | 少于/多于渠道限制 |
| `IMAGE_TOO_LARGE` | blocker | 超过单图体积 |
| `IMAGE_TOO_SMALL` | warning | 小于建议尺寸 |
| `RATIO_MISMATCH` | warning | 比例不在推荐范围 |
| `TRANSPARENT_BACKGROUND` | warning | 透明背景在 JPG 下可能变黑/白 |
| `TITLE_TOO_LONG` | blocker | 超过渠道上限 |
| `TITLE_NEAR_LIMIT` | warning | 接近上限 |
| `BODY_TOO_LONG` | blocker | 超过正文上限 |
| `TAGS_TOO_MANY` | warning | 标签超过建议数量 |
| `MISSING_COVER` | blocker | 没有封面 |
| `COVER_SAFE_AREA` | warning | 标题/Logo 进入裁切危险区 |
| `MISSING_ALT` | info | 图片缺少描述 |
| `UNLICENSED_ASSET` | warning | 版权未知 |
| `AI_LABEL_MISSING` | warning | AI 内容未标识（按平台要求） |
| `LINK_NOT_ALLOWED` | warning | 公众号正文外链限制 |
| `DUPLICATE_PUBLISH` | warning | 同内容已发布过 |
| `TOKEN_EXPIRED` | blocker | 凭据失效 |
| `IP_NOT_WHITELISTED` | blocker | 微信 IP 白名单未配置 |
| `MISSING_ASSET` | blocker | 引用的素材文件不存在 |

检查结果要能「一键修复」的尽量修复：压缩图片、裁切到比例、补封面、截断标题、移除多余标签、转不透明背景。

### 5.4 微信公众号

#### 图片消息（贴图，首版重点）

**前置条件**

- 公众号/服务号具备草稿箱与发布接口权限（通常需认证）；
- 后台配置 IP 白名单；
- AppID / AppSecret；
- 图片走永久素材（`material/add_material?type=image`），不是临时素材。

**调用链**

```text
1. GET  /cgi-bin/token?grant_type=client_credential&appid=...&secret=...
2. POST /cgi-bin/material/add_material?access_token=...&type=image   （逐张，multipart）
3. POST /cgi-bin/draft/add?access_token=...                          （article_type=newspic）
4. POST /cgi-bin/freepublish/submit?access_token=...                 （可选）
5. POST /cgi-bin/freepublish/get?access_token=...                    （轮询）
```

`draft/add` 关键字段：`article_type: "newspic"`、`title`、`content`（纯文本）、`image_info.image_list[].image_media_id`、`cover_info.crop_percent_list`、评论开关。详细字段与错误码见原文档 4.4 节。

**产品决策**

- 默认「存草稿」，用户在公众号后台确认后再发布；高级选项才显示「直接发布」。
- 图片顺序 = 作品图片顺序，第一张为封面；支持在变体里单独指定封面。
- 封面裁切提供 1:1 / 16:9 / 2.35:1 预览，避免后台裁切后标题被切。
- 正文默认纯文本；如果用户填了 HTML，做白名单清洗（只允许基础标签）。
- 素材 `media_id` 缓存，按图片 hash 去重；提供「清理微信素材缓存」入口。

#### 图文消息（可选）

- 正文图片先 `media/uploadimg` 上传，替换为微信 URL；封面用永久素材。
- HTML 必须内联样式，微信会过滤 class/外链 CSS/JS；代码块、表格、复杂布局要做降级。
- 外链只允许公众号白名单域名；文末「阅读原文」单独配置。
- 首版可以只支持「标题 + 段落 + 图片 + 引用 + 列表」的安全子集，复杂 Markdown 提示「建议用图片消息」。

#### 错误与降级

| 错误 | 处理 |
| --- | --- |
| `40001/42001` token 失效 | 自动刷新一次，仍失败重新配置 |
| `40164` IP 不在白名单 | 显示当前出口 IP + 后台配置指引 |
| `45009` 接口超限 | 显示配额/重试时间，禁止连续重试 |
| `48001` API 未授权 | 提示账号类型/认证问题，自动降级「仅导出发布包」 |
| `40007` media_id 无效 | 清除该图缓存，重新上传 |
| 网络超时 | 指数退避重试 2 次，保留已完成步骤 |

### 5.5 小红书

#### 首版：半自动（推荐）

```text
检查通过
→ 生成小红书变体（3:4 图片、标题 ≤20、正文 ≤1000、标签）
→ 复制标题/正文/标签（分开复制，避免富文本污染）
→ 打开 creator.xiaohongshu.com/publish/publish
→ 打开图片文件夹（按 01、02… 命名）
→ 显示发布清单：图片数、标题字数、正文长度、标签、封面建议
→ 用户手动上传 + 粘贴 + 发布
→ 回到应用标记「已发布」，粘贴链接
```

体验优化：

- 「复制全部」按平台字段分段写入剪贴板，并提供「逐项复制」；
- 图片文件夹自动按顺序命名，支持「复制图片到剪贴板」；
- 记住上次窗口位置/发布选项；
- 发布完成后弹出「记录数据」提醒；
- 失败/放弃时可回到变体继续改。

#### 可选：本地浏览器桥（阶段 E）

如果确实要接近「一键」，建议独立可选组件，不塞进主应用：

- 本地 `127.0.0.1` 桥接进程（Playwright + 持久化 Profile）；
- 用户手动登录一次；应用只发送 `bundlePath`；
- 选择器集中在 `selectors.js`，平台改版只修一处；
- 默认「填完不提交」，最后一步由用户确认；
- 明确标注「实验性、可能触发风控、账号风险自负」；
- 不保存密码、不绕过验证码、不做批量矩阵、不做自动评论/私信。

#### 小红书规格（可配置，需以平台最新规则为准）

- 图片 1–18 张，推荐 3:4；
- 标题 ≤ 20 字；
- 正文 ≤ 1000 字；
- 标签建议 ≤ 10 个；
- 封面第一张最重要；
- 支持地点、@、可见范围等字段（首版可只做标题/正文/标签/图片）。

### 5.6 跨平台文案与图片适配

**不是把同一段文案复制两次**，而是生成「平台变体」：

| 维度 | 小红书 | 公众号图片消息 |
| --- | --- | --- |
| 标题 | 短、钩子、≤20 字 | 可稍长、信息完整 |
| 正文 | 口语化、emoji、分段、标签 | 书面、段落、无标签 |
| CTA | 收藏/评论/关注 | 阅读原文/关注 |
| 图片 | 3:4、封面强 | 3:4 或 1:1、首图封面 |
| 标签 | 独立标签 | 无 |
| 链接 | 不支持外链 | 阅读原文 |

**适配规则**

- 标题：优先保留主谓宾，截断时避免断在词中间；提供 3 个候选。
- 正文：按平台长度裁剪，保留开头钩子和结尾 CTA；超长时提示「建议拆成多篇/用图片承载」。
- 标签：从正文 `#话题` 抽取 + 推荐标签 + 手动；去重、限个数。
- Emoji：小红书可保留，公众号按需移除。
- 图片：按渠道比例裁切/留白；封面单独指定；安全区检查；透明背景转不透明。
- 提供「差异对比」视图：左右两栏显示两个变体的标题/正文/图片，避免发错。

### 5.7 队列、定时、幂等与恢复

- **发布队列**：本地串行（同一渠道同时 1 个任务），支持取消、重试、查看日志。
- **定时发布**：
  - 应用运行时，到点执行；
  - 应用关闭时，不承诺后台发布；下次启动提示「有 N 个错过的排期」；
  - 可导出 `.ics` 日历提醒，作为兜底；
  - 不做云端定时（除非未来提供中继，且显式说明）。
- **幂等键**：`contentHash + channelId + imageHashes`；重复点击提示「已发布/是否重试」。
- **失败恢复**：保留已上传 `media_id`、草稿 ID；重试只补缺失步骤；提供「从断点继续」。
- **并发锁**：同一作品/渠道只允许一个进行中的发布。
- **日志**：本地记录阶段、耗时、错误码；不记录 secret、不记录正文全文（只存 hash + 标题摘要）。

### 5.8 凭据与安全

- AppSecret / API Key 只存 OS Keychain（Rust `keyring`），前端只读「已配置」状态。
- 微信 token 缓存在内存 + 加密文件（可选），过期自动刷新；不写 localStorage。
- 请求走 Rust `reqwest`：超时、重试、代理、TLS 统一配置；避免前端 CORS。
- 日志脱敏：`app_secret`、`access_token`、`api_key` 永不回显。
- 路径校验：发布包读写拒绝 `..`、绝对路径逃逸、符号链接逃逸。
- 网络边界：供应商 base URL 白名单；禁止访问内网/元数据地址（本地 ComfyUI 需显式允许 `127.0.0.1`）。
- 权限最小化：Tauri capability 只加必要项；网络请求在 Rust 侧则不需要前端 http 权限。

## 6. 运营

### 6.1 定位

运营模块不做「大而全的社媒管理系统」，而是围绕个人/小团队的 **内容节奏与复盘闭环**：

```text
选题 → 排期 → 发布 → 数据 → 复盘 → 复用/调整
```

三个原则：

- **本地优先**：数据默认只在本机，可导出 CSV/JSON；
- **手动友好**：没有 API 的平台允许手动录入/CSV 导入，不强迫自动化；
- **轻量**：首版不做复杂归因、不做团队权限、不做实时大屏。

### 6.2 内容管道与日历

**内容管道（Kanban）**

```text
灵感 Inbox → 写作中 → 待发布 → 已排期 → 已发布 → 待复盘 → 已归档
```

- 卡片可直接从「灵感」转作品；
- 显示平台、封面、就绪度、计划时间；
- 拖拽改状态；状态变更写本地历史。

**日历**

- 月/周视图，按平台分泳道（小红书 / 公众号）；
- 显示已排期、已发布、待复盘；
- 点击空白格新建排期；
- 支持重复系列（每周三发）；
- 导出 `.ics`，可导入系统日历；
- 提醒：发布前 1 小时、发布后 24 小时记录数据。

### 6.3 选题与系列

**灵感库**

```json
{
  "id": "idea_...",
  "title": "为什么你的封面没人点",
  "angle": "反常识 + 3 个案例",
  "audience": "新手博主",
  "source": "评论区/文章/播客",
  "tags": ["封面", "增长"],
  "status": "inbox",
  "workId": null
}
```

- 快速捕获（快捷键/剪贴板/链接）；
- 标签、来源、受众、钩子；
- 一键转作品，带标题和初始大纲；
- 关联参考素材（截图、链接、竞品）。

**系列**

- 系列名、期数、统一封面模板、统一 CTA、统一标签；
- 「新建下一期」自动复制模板与样式；
- 系列进度、每期数据对比；
- 系列合集/目录页。

**品牌套件 BrandKit**

- Logo、头像、简介、二维码、品牌色、字体、页脚署名、免责声明、CTA 库；
- 所有封面/图集/发布变体共享；
- 导出时可选「包含品牌套件」。

### 6.4 数据来源与指标

| 来源 | 方式 | 可靠性 | 首版 |
| --- | --- | --- | --- |
| 微信公众号 | 官方 `datacube` 接口（需权限） | 高 | 做 |
| 微信公众号 | 手动录入 | 高（人工） | 兜底 |
| 小红书 | 手动录入 | 高（人工） | 做 |
| 小红书 | CSV 导入（创作中心导出/自建模板） | 中 | 做 |
| 小红书 | 截图 OCR | 中 | 后续 |
| 小红书 | 浏览器桥抓取 | 低/有风险 | 不做默认 |
| 其他平台 | 手动/CSV | 中 | 后续 |

**统一指标口径**

| 指标 | 定义 | 备注 |
| --- | --- | --- |
| 阅读/曝光 | 平台展示或阅读数 | 各平台口径不同，分开存 |
| 点赞 | like | |
| 收藏 | save/favorite | 小红书权重高 |
| 评论 | comment | |
| 分享 | share/repost | |
| 涨粉 | 发布后新增关注 | 公众号可拉，小红书手动 |
| 点击 | 链接/二维码/阅读原文 | 需要渠道码 |
| 转化 | 私信/加微/购买 | 手动或渠道码 |

派生指标：互动率 =（点赞+收藏+评论+分享）/ 阅读；收藏率、评论率、涨粉率、点击率。**不要跨平台直接比较绝对值**，UI 要标注口径。

**快照节奏**

- 发布后 24h、72h、7d 自动提醒记录；
- 微信可自动拉取（有权限时）；
- 小红书手动/CSV；
- 同一记录可追加多个快照，形成趋势。

### 6.5 复盘

**复盘卡**是运营模块的核心产出，不是一张大报表：

```text
作品：把想法变成作品
平台：小红书 / 公众号
发布时间：周三 20:10
数据：阅读 1.2w / 赞 320 / 藏 890 / 评 45 / 涨粉 28
亮点：封面对比强；标题有数字；正文前 2 行给结论
问题：第 5 页信息太密；CTA 太晚
假设：下次把 CTA 放第 2 页，封面换真人/手部
下次动作：模板 A + 标题公式 B
```

- 自动生成「数据摘要」；
- 手动填写「亮点/问题/假设/下一步」；
- 关联实验（封面 A/B、标题 A/B）；
- 按标签/系列/平台聚合，找出高表现模式；
- 月度/季度报告：发布数、平均互动、最佳作品、最差作品、复用率。

### 6.6 实验（A/B）

- 同一个作品保存 2–3 个封面/标题候选；
- 发布时选择一个，或按渠道分配；
- 记录实验组、时间、数据；
- 结果只做「探索性」展示，不承诺统计显著性；
- 实验库：沉淀「哪种封面/标题/发布时间更适合我」。

**注意**：小红书/公众号无法做真正的同人群分流 A/B；这里的 A/B 是「跨时间/跨作品对比」，UI 要说明局限。

### 6.7 内容复用与增长钩子

**一鱼多吃**

```text
长文
├─ 公众号图文
├─ 公众号图片消息（9 图）
├─ 小红书图文（9 图 + 短文案）
├─ 微博九宫格
├─ 朋友圈 1 张金句卡
└─ 短视频脚本/口播稿（后续）
```

- 一键「派生为」另一种作品类型；
- 保留素材引用，不重复占空间；
- 自动改写标题/正文长度；
- 旧文翻新：换封面、补数据、加新案例，标记「更新版」。

**增长钩子**

- CTA 库：关注、收藏、评论关键词、私信、领取资料；
- 二维码/渠道码：区分公众号、小红书、线下；
- 资料包/清单：作为引流素材，放素材库；
- 评论区首评模板（手动复制，不自动发）；
- 金句卡/目录页/结尾页模板；
- 「系列合集」页，提升收藏。

### 6.8 自动化规则（本地、可关闭）

| 规则 | 触发 | 动作 |
| --- | --- | --- |
| 发布提醒 | 排期前 1 小时 | 系统通知 |
| 数据提醒 | 发布后 24h/72h/7d | 提醒记录/拉取 |
| 周报 | 每周一 | 生成本地摘要 |
| 陈旧草稿 | 7 天未编辑 | 列表提示 |
| 未使用素材 | 30 天未引用 | 清理建议 |
| 封面疲劳 | 同系列连续 3 期同模板 | 建议换版式 |
| 最佳时间 | 历史数据足够 | 建议发布时段（仅供参考） |

不做：自动评论、自动私信、自动关注、批量养号、绕过验证码。

### 6.9 隐私与数据

- 指标、作品、素材默认只存本机；
- 不接入第三方统计 SDK；
- 导出 CSV/JSON 由用户主动触发；
- 删除作品可选择「同时删除指标」；
- 云端同步/团队协作不在首版，未来若做必须显式 opt-in。

### 6.10 UI

```text
运营
├─ 概览：本周发布、待复盘、总阅读、最佳作品、就绪度分布
├─ 日历：月/周，平台颜色区分 + 筛选，拖拽排期
├─ 内容库：作品列表 + 筛选 + 批量派生
├─ 数据：指标表 + 趋势图 + 导出
└─ 复盘：复盘卡列表 + 标签聚合 + 月报
```

### 6.11 MVP 与验收

**MVP（阶段 D）**

- 内容管道（状态 + 列表）；
- 日历（月/周 + 提醒 + `.ics` 导出）；
- 手动录入指标 + CSV 导入；
- 微信 `datacube` 拉取（有权限时）；
- 复盘卡 + 标签聚合；
- 周报摘要。

**验收**

- [ ] 从发布完成到记录 24h 数据 ≤ 2 次点击；
- [ ] 小红书/公众号指标分开存储，口径标注清楚；
- [ ] 日历排期不会因应用关闭而「静默失败」，下次启动有提示；
- [ ] 复盘卡可导出 Markdown/CSV；
- [ ] 删除作品/指标有确认，不可误删；
- [ ] 所有运营数据可一键导出，无云端依赖。

### 7.6 状态归属

- `useStudioDocument`：文档源、分页、预览、现有导出设置。
- `useWork`：作品元数据、封面、图片序列、主文案、变体引用。
- `useAssetLibrary`：素材索引、选择、引用、回收站。
- `usePublishQueue`：发布任务、进度、历史。
- `useInsights`：指标、复盘、聚合。
- 组件内只保留 UI 临时状态（弹窗开关、拖拽 hover、当前 tab）。

避免把素材/发布/指标塞进 `useStudioDocument`；它已经 1,295 行，继续膨胀会难以维护。跨模块通过 `App.vue` 传事件，或由 `useWork` 组合。

### 7.7 浏览器降级

- 素材：IndexedDB + object URL；刷新后尽量恢复；不支持原生缩略图时用 canvas。
- 文件选择：`<input type="file">`；导出：下载 Blob。
- 发布：微信 API 需要 Rust/Keychain，浏览器模式禁用并提示「请在桌面端使用」；小红书半自动可复制/打开网页，但打开文件夹降级为下载 ZIP。
- 生成：若供应商支持 CORS 可直连；否则提示桌面端。Jaaz 云端 API 默认走 Rust（Keychain + 无 CORS），浏览器模式只保留确定性生成和 handoff 导出。
- 任何降级都不能白屏；按钮要么可用，要么给出明确原因。

### 7.8 测试

- 纯函数单测（Vitest，需新增脚本）：变体检查、标题截断、正文转换、指标计算、发布包 manifest。
- Rust 单测：hash、路径校验、缩略图、manifest 解析。
- 微信 API 用 mock server（WireMock/自建 axum）覆盖 40001/40164/45009/48001/超时。
- 组件测试不做全量；关键弹窗用轻量快照/交互测试。
- 手动 E2E：微信测试号、真实小红书账号（半自动）、macOS/Windows 各一次。
- 不在 CI 使用真实凭据/真实账号。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 公众号无 API 权限/个人订阅号 | 微信直连不可用 | 默认提供发布包 + 手动上传；48001 自动降级 |
| 出口 IP 变化导致 40164 | 直连失败 | 显示当前 IP + 白名单指引；可选自建中继 |
| 微信 API/字段变更 | 发布失败 | 适配器隔离；错误码兜底；manifest 可手动使用 |
| 小红书自动化触发风控 | 账号风险 | 默认半自动；桥接独立、需确认、限速、明确风险 |
| AI 图片文字乱码 | 封面不可用 | 文字永远由应用排版，AI 只出画面 |
| AI 成本/延迟 | 体验差 | 缓存、低清预览、批量候选、额度提示、确定性回退 |
| Jaaz 接口非公开/易变 | 生图失败 | 适配器隔离；404/字段变更时降级 handoff；版本探测 |
| Jaaz 许可/再分发限制 | 法律风险 | 只走 HTTP，不复制/内嵌代码；商业分发前取得许可并法务复核 |
| Jaaz 云端数据出境 | 隐私风险 | 首次明确同意；敏感内容用本地 handoff/ComfyUI |
| Jaaz 额度/Token 失效 | 无法生成 | 402/429 提示；回退确定性生成；不阻塞主流程 |
| 图片版权/AI 合规 | 法律/平台风险 | 记录 license/来源/AI 标识；未知版权 warning；上线前复核法规 |
| 素材膨胀/重复 | 存储与性能 | 内容 hash 去重、缩略图、未使用清理、回收站 |
| 素材误删/引用断裂 | 作品损坏 | 引用检查、软删除、重新链接、备份 |
| 发布包写入中断 | 半成品 | 临时目录 + 原子 rename；失败清理 |
| 18 张图内存峰值 | 卡顿/崩溃 | 逐张落盘、Rust 读文件、限制并发、逐页释放 canvas |
| 版式高度估算偏差 | 内容溢出 | 固定 aspect-ratio、共享度量、预览/导出一致（原文档） |
| UI 功能膨胀 | 学习成本 | 一级模式 + 检查器；素材库 Overlay；渐进披露 |
| 两处 SettingsPanel 漏改 | 窄屏缺功能 | 共享 props/emits 常量；验收覆盖抽屉 |
| i18n 不同步 | 英文缺 key | 同 PR 改两 locale；可选校验脚本 |
| 本地数据损坏 | 丢作品 | 原子写、备份、schema 迁移、导出 |

## 10. 端到端验收

**场景 1：长文 → 小红书 + 公众号**

- [ ] 打开 2,000 字 Markdown，自动分成 8 页；
- [ ] 封面工坊 3 分钟做出 3:4 封面，标题不溢出；
- [ ] 生成两个变体，标题/正文/标签各自合规；
- [ ] 检查清单无 blocker；一键修复 2 个 warning；
- [ ] 小红书：3 分钟内完成复制/上传/发布；
- [ ] 公众号：成功建草稿，后台可见 8 张图 + 标题 + 正文；
- [ ] 发布记录可查，重复发布有提示。

**场景 2：照片 → 图集**

- [ ] 拖入 12 张照片，自动去重/缩略图；
- [ ] 选 9 张，套模板，批量裁 3:4；
- [ ] 替换其中 1 张，版式与引用保持；
- [ ] 导出 `.mcard`，另一台机器打开不丢图；
- [ ] 发布包图片顺序、封面、文案正确。

**场景 3：运营闭环**

- [ ] 复盘卡记录亮点/问题/下一步；
- [ ] 周报生成本地摘要；
- [ ] 从复盘卡「派生下一期」，模板/CTA 复用。

## 11. 需要确认的决策

1. **主用户是谁？** 个人创作者优先，还是品牌/小团队优先？这决定多账号、审批、协作是否进首版。
2. **「微信贴图」具体指哪个入口？** 公众号图片消息（本文假设）、朋友圈、还是视频号图文？
3. **公众号账号类型/权限？** 已确认有接口权限；实现前仍需 AppID/AppSecret、IP 白名单、草稿箱/发布权限。
4. **小红书能接受半自动吗？** 已确认按最简单的半自动；不做浏览器桥。
5. **AI 生图走云还是本地？** 已确认 **Jaaz 最后做**，MVP 只留 `ImageProvider` 接口；后续接云端 API + handoff。
6. **是否需要多账号/定时？** 这会显著影响凭据、队列、日历和 UI。
7. **是否需要云端同步/团队协作？** 首版建议不做；若要做，需要重新评估本地优先承诺。
8. **首发平台是 macOS 还是 Windows？** 影响 Keychain、路径、WebView 测试优先级。
9. **是否要做公众号图文消息（HTML）？** 复杂度高，建议首版只做图片消息 + 草稿。
10. **商业化方式？** 当前是个人使用，暂不涉及商业分发。
11. **Jaaz 的接入方式与许可？** 已确认个人使用、不做商业分发；最后做时采用云端 API + handoff，不复制/内嵌源码。

## 附录 B：术语

| 术语 | 含义 |
| --- | --- |
| 作品 Work | 一次内容创作的容器，可派生多个平台变体 |
| 变体 Variant | 面向某渠道的发布版本（文案/图片/封面覆盖） |
| 素材 Asset | 可复用的图片/贴纸/背景/生成结果 |
| 发布包 Bundle | manifest + images + copy，渠道适配器的唯一输入 |
| 就绪度 Readiness | 发布前检查的量化分数 |
| 素材血缘 | 素材的来源、生成信息、版权、引用关系 |
| 一鱼多吃 | 同一主内容派生多平台/多形式 |
| 半自动 | 应用准备物料并打开平台，用户完成最后发布 |
| Jaaz | 开源 AI 设计 Agent（jaaz.app），本文用作可选生图引擎 |
