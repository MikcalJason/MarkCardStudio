# MarkCard Studio 改造点梳理与决策清单

> 状态：实施评审稿（Phase 4A 已完成）
> 日期：2026-10-21
> 关系：汇总 [`image-content-suite-design.md`](./image-content-suite-design.md)、[`ui-architecture-design.md`](./ui-architecture-design.md)、[`publishing-and-image-layout-design.md`](./publishing-and-image-layout-design.md) 的改造点，标出需要拍板的问题。
> 结论：方向成立，但当前设计覆盖「生成 → 管理 → 发布 → 运营」全链路，**不能一次性全做**。建议先锁定 MVP，再按依赖顺序实施。
> 实施进度：Phase 1 见 [`phase-1-implementation.md`](./phase-1-implementation.md)；Phase 2 见 [`phase-2-implementation.md`](./phase-2-implementation.md)；Phase 3 见 [`phase-3-implementation.md`](./phase-3-implementation.md)；Phase 4A（发布变体 / 检查 / 发布包 / 小红书半自动）见 [`phase-4-implementation.md`](./phase-4-implementation.md)。

## 0. 结论先行

### 0.1 三句话

1. **产品方向没问题**：从「Markdown 排版工具」升级为「图文作品工作台」，用「作品 / 变体 / 素材」承载多平台发布，是合理的。
2. **当前范围偏大**：AI 生图、素材库、双平台发布、运营、A/B、多账号同时设计，首版必须砍。
3. **5 个阻塞级问题已确认**：Jaaz（`../jaaz` v1.0.30）、个人使用、公众号有权限、小红书半自动、素材采用「全局库 + 项目镜像」；首版做 MVP，**Jaaz 放最后做**。还剩 2 个非阻塞问题：导航、运营数据来源。

### 0.2 建议的 MVP

```text
作品/素材模型
  + 素材库（导入/搜索/引用/替换/回收站）
  + 封面工坊（模板 + 确定性背景）
  + 发布检查 + 发布包
  + 微信公众号草稿
  + 小红书半自动
```

**暂缓**：Jaaz / AI 生图（最后做，MVP 只留 `ImageProvider` 接口）、运营报表、A/B、多账号、浏览器自动化、云端同步。

理由：素材库和作品模型是发布/运营的地基；封面决定点击；发布检查和微信草稿/小红书半自动直接解决「发得出去」；运营可以先用 CSV/手动数据后补。

## 1. 改造点全景

### 1.1 产品模型

| 改造点 | 内容 | 影响 |
| --- | --- | --- |
| 作品 Work | 一次创作的容器：封面、图片序列、主文案、主题、画布 | 新增核心对象 |
| 变体 Variant | 面向渠道的版本：标题/正文/标签/图片顺序/封面覆盖 | 支撑双平台 |
| 素材 Asset | 可复用图片：hash、来源、版权、AI 信息、使用关系 | 素材库基础 |
| 发布记录 PublishRecord | 渠道、模式、远端 ID、状态、错误 | 幂等/重试/历史 |
| 指标快照 MetricSnapshot | 阅读/点赞/收藏/评论/分享/涨粉 | 运营复盘 |
| 三种创作模式 | 写作 / 图集 / 海报 | 覆盖长文、图集、单图 |

### P0：不确认就没法定实现

#### 1. 「Jazz AI」到底是不是 Jaaz？

**状态：已确认是 Jaaz。**

- 同级项目目录有源码：`../jaaz`，v1.0.30，默认端口 `57988`。
- 可以按本地源码验证接口，而不是只依赖 GitHub 文档。
- 首版仍建议云端 API + handoff；本地 sidecar 作为后续可选。

#### 2. Jaaz 的许可与接入方式

**状态：已确认个人使用，不涉及商业分发。**

- 风险从「商业许可/再分发」降为「个人使用 + 不复制源码」。
- 仍不建议把 Jaaz 源码复制进 MarkCard、修改后分发，或打包进安装包。
- **Jaaz 最后做**；到时只做云端 API + handoff，本地 sidecar 可选，直接调用用户已安装的 Jaaz。
- 不做商业分发，不代表可以忽略 Jaaz 的使用条款；只是不需要走商业许可谈判。

#### 3. 微信公众号的账号资质

**状态：已确认有权限。**

- 实现前仍需准备：AppID、AppSecret、IP 白名单、草稿箱/发布接口权限。
- 默认「存草稿」，后台确认后再发；直接发布作为高级选项。
- 若运行时遇到 48001/40164，仍要能降级到「发布包 + 手动上传」。

#### 4. 小红书半自动是否接受？

**状态：已确认，按最简单的来。**

- 首版只做：复制标题/正文/标签 → 打开创作平台 → 打开图片文件夹 → 用户手动上传/发布 → 回应用标记「已发布」。
- 不做浏览器自动化、OCR、自动评论/私信。
- 发布检查只做技术校验（数量/尺寸/标题/正文/标签），不承诺平台审核结果。

#### 5. 素材存储以哪边为准？

**状态：已确认，采用「全局库为主 + 项目镜像」。**

| 维度 | 全局素材库 | 项目目录 `assets/` |
| --- | --- | --- |
| 位置 | 应用数据目录 `library/` | 文档同目录 `assets/` |
| 角色 | 内容主库、索引、去重、标签、版权、使用关系 | Markdown 引用镜像，保证可移植 |
| 范围 | 所有作品 | 当前项目 |
| 复用 | 高，跨作品复用 | 低，只服务当前项目 |
| 引用 | `assetId` + 索引 | 相对路径 `assets/<hash>.<ext>` |
| 导出 | 通过 `.mcard` 收集引用素材 | 复制文件夹即可打开 |

- 全局库存一份原图（内容 hash），项目 `assets/` 只放被当前项目引用的素材。
- 导入流程：hash → 库中不存在则复制进库 → 确保项目镜像存在（复制/硬链接，失败回退复制）→ 插入相对路径 → 记录映射。
- 导出 `.mcard` 只收集引用素材，不打包整个全局库。
- 删除：先移除项目引用；全局素材无任何项目引用时才允许清理。
- 不使用绝对路径/符号链接：换机器会断，Windows/移动硬盘不可靠。

> 详细布局见主设计文档 4.5 与 7.4。

### P1：影响范围和工期

#### 6. 首版到底做哪几块？

**状态：已确认首版做 MVP，Jaaz 最后做。**

建议按「地基 → 创作 → 发布 → 运营 → Jaaz」排：

| 版本 | 范围 |
| --- | --- |
| MVP | 作品/素材模型、素材库、封面工坊、确定性背景、发布检查、发布包、微信草稿、小红书半自动 |
| v1 | 图片编辑、发布中心、运营概览/日历/手动数据 |
| v2 | A/B、AI 建议、浏览器桥、多账号、定时、云同步 |
| **最后** | **Jaaz 云端生图 + handoff**（独立阶段，不阻塞 MVP/v1） |

MVP 明确不做：Jaaz/AI 生图（只留 `ImageProvider` 接口）、运营报表、A/B、多账号、浏览器桥。

#### 7. 3+1 导航是否接受？

- 推荐：一级「创作 / 发布 / 运营」，创作内部「写作/图集/海报」。
- 备选：一级「写作 / 图集 / 发布 / 运营」四个入口。

**需要确认**：是否接受 3+1？如果坚持 4 入口，发布按钮和发布模式的命名要再设计。

#### 8. 素材管理是浮层还是独立页面？

- 当前设计：全局浮层，任何模式可打开。
- 备选：一级「素材」页面，适合大量素材/批量管理。

**需要确认**：你的使用习惯更偏「随时插入」还是「集中整理」？两者可以并存（浮层 + 全屏页），但首版只做一个主入口。

#### 9. 快速发布弹窗 + 发布中心是否重复？

- 设计：当前作品用弹窗，批量/队列/历史用发布中心。
- 风险：两个入口做同一件事，用户会困惑。

**需要确认**：是否保留双入口？建议保留，但弹窗只做「当前作品」，成功后引导去发布中心。

#### 10. 定时发布/多账号是否进首版？

- 定时依赖应用运行；关闭应用不保证发布。
- 多账号会显著增加凭据、队列、UI 复杂度。

**建议**：首版单账号 + 本地排期提醒；多账号/后台定时后置。

### P2：体验/合规/成本

#### 11. 运营数据怎么来？

- 微信：datacube API（需权限）或手动。
- 小红书：手动/CSV；截图 OCR/浏览器抓取有风险。

**需要确认**：能否接受首版「手动录入 + CSV」？是否必须自动拉小红书数据？

#### 12. 浏览器模式要支持到什么程度？

- 发布/Keychain/Jaaz 云端 API 都依赖桌面端。
- 浏览器模式只能做编辑、确定性生成、导出发布包。

**需要确认**：浏览器模式是否只是开发预览，还是要作为正式入口？

#### 13. AI 内容标识与版权

- 国内 AI 生成内容标识要求、平台 AI 标注、参考图版权。
- 需要确认：是否强制显示「AI 生成」标识？是否允许用户关闭？

**建议**：默认标识；不提供「去除标识」；发布前提示版权状态。

#### 14. 视觉方向

- 当前设计沿用现有浅色玻璃 + 蓝色主色。
- 备选：更中性的「内容工具」风格（减少渐变/玻璃，突出画布）。

**需要确认**：是否保持现有视觉语言？还是借这次改版做一次 UI 视觉升级？

## 4. 建议的决策顺序

```text
已完成：Jaaz 身份 / 个人使用 / 公众号权限 / 小红书半自动 / 素材存储 / MVP 范围
待确认：3+1 导航 / 运营数据来源
```

**不要先做**：发布按钮、Jaaz 生图面板、运营报表。它们都依赖作品/素材模型，先做会返工。

## 5. 实施顺序建议（与 UI 文档一致）

| 阶段 | 内容 | 退出标准 |
| --- | --- | --- |
| Phase 1 ✅ | 壳、3+1、Inspector、`useWorkspaceUi`、合并两份 SettingsPanel | 写作无回归；窄屏可用 |
| Phase 2 ✅ | 作品/素材模型、素材库网格/列表、导入/去重/引用、图集序列 | 素材可复用、删除不坏作品；图集可导出 |

- 多平台矩阵批量发布；
- 自动评论/私信/关注；
